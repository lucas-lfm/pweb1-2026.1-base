# RetroMarket — Requisitos e Histórias de Usuário

## 1. Visão do projeto

**RetroMarket** é uma plataforma de anúncios especializada em videogames retrô.

A plataforma permite que usuários publiquem e consultem anúncios de **consoles, jogos, acessórios e kits**, informando características relevantes para o mercado de retrogames, como **condição**, **completude**, **plataforma** e **categoria**.

O projeto será utilizado como exemplo didático na disciplina de **Programação WEB I**, servindo de contexto para o desenvolvimento incremental de uma aplicação web back-end e de sua API.

---

# 2. Atores

| Ator | Descrição |
|---|---|
| **Visitante** | Pessoa que acessa a plataforma sem estar autenticada. Pode consultar anúncios e realizar o cadastro. |
| **Usuário autenticado** | Usuário que possui uma conta e realizou login. Pode publicar e gerenciar seus próprios anúncios, além de utilizar favoritos. |

> **Observação:** o escopo inicial não contempla um perfil de administrador. Essa funcionalidade pode ser adicionada posteriormente como extensão do projeto.

---

# 3. Conceitos principais do domínio

## 3.1 Categorias de anúncio

Os anúncios podem representar:

- **Console**
- **Jogo**
- **Acessório**
- **Colecionável**
- **Kit / Bundle**

## 3.2 Condição

A condição representa o estado físico/comercial do item:

- **Novo (Lacrado)**
- **Seminovo (Excelente)**
- **Usado (Bom estado)**
- **Recondicionado**
- **Com Defeito / Sucata**

## 3.3 Completude

A completude representa o quanto do conjunto original acompanha o item:

- **Completo (CIB)**
- **Loose (Avulso)**
- **Incompleto / Personalizado**

## 3.4 Status do anúncio

Um anúncio pode assumir os seguintes estados:

- **Ativo**
- **Reservado**
- **Vendido**
- **Inativo**

# 4. Requisitos funcionais

Os requisitos funcionais descrevem **o que o sistema deve fazer**.

## RF01 — Cadastro de usuário

O sistema deve permitir que um visitante crie uma conta informando:

- nome;
- e-mail;
- senha.

O e-mail utilizado no cadastro deve ser único.

**Prioridade:** Alta

---

## RF02 — Autenticação de usuário

O sistema deve permitir que um usuário cadastrado realize login utilizando e-mail e senha.

**Prioridade:** Alta

---

## RF03 — Consulta de anúncios

O sistema deve permitir que visitantes e usuários autenticados consultem os anúncios disponíveis na plataforma.

A consulta deve apresentar, no mínimo:

- título;
- preço;
- plataforma;
- categoria;
- condição;
- completude;
- status;
- imagem principal, quando disponível.

**Prioridade:** Alta

---

## RF04 — Consulta de detalhes de um anúncio

O sistema deve permitir visualizar os detalhes de um anúncio específico.

A consulta deve apresentar as informações cadastradas do anúncio e suas imagens.

**Prioridade:** Alta

---

## RF05 — Cadastro de anúncio

O sistema deve permitir que um usuário autenticado publique um anúncio.

Um anúncio deve possuir, no mínimo:

- título;
- descrição;
- preço;
- categoria;
- plataforma;
- condição;
- completude;
- localização.

O usuário responsável pelo anúncio deve ser identificado pelo sistema a partir da autenticação.

**Prioridade:** Alta

---

## RF06 — Alteração de anúncio

O sistema deve permitir que o proprietário altere as informações de seu anúncio.

**Prioridade:** Alta

---

## RF07 — Exclusão de anúncio

O sistema deve permitir que o proprietário retire seu anúncio da plataforma.

**Prioridade:** Alta

---

## RF08 — Consulta dos meus anúncios

O sistema deve permitir que um usuário autenticado consulte os anúncios publicados por ele.

**Prioridade:** Alta

---

## RF09 — Alteração do status do anúncio

O sistema deve permitir que o proprietário altere o status de seu anúncio.

Os status disponíveis são:

- Ativo;
- Reservado;
- Vendido;
- Inativo.

**Prioridade:** Média

---

## RF10 — Cadastro de fotos do anúncio

O sistema deve permitir associar uma ou mais fotos a um anúncio.

Para o escopo inicial, as imagens podem ser representadas por suas URLs.

**Prioridade:** Média

---

## RF11 — Definição da foto principal

O sistema deve permitir definir uma das fotos associadas ao anúncio como imagem principal.

**Prioridade:** Média

---

## RF12 — Pesquisa de anúncios

O sistema deve permitir pesquisar anúncios utilizando termos relacionados ao título ou à descrição.

**Prioridade:** Média

---

## RF13 — Filtro por plataforma

O sistema deve permitir filtrar anúncios por plataforma.

Exemplos:

- Atari 2600;
- Super Nintendo;
- Nintendo 64;
- Mega Drive;
- PlayStation;
- PlayStation 2;
- Game Boy;
- Dreamcast.

**Prioridade:** Média

---

## RF14 — Filtro por categoria

O sistema deve permitir filtrar anúncios por categoria.

**Prioridade:** Média

---

## RF15 — Filtro por condição

O sistema deve permitir filtrar anúncios pela condição do produto.

**Prioridade:** Média

---

## RF16 — Filtro por completude

O sistema deve permitir filtrar anúncios pela completude do produto.

**Prioridade:** Média

---

## RF17 — Filtro por faixa de preço

O sistema deve permitir consultar anúncios considerando um preço mínimo e/ou máximo.

**Prioridade:** Média

---

## RF18 — Ordenação dos anúncios

O sistema deve permitir ordenar os anúncios segundo critérios como:

- menor preço;
- maior preço;
- anúncios mais recentes.

**Prioridade:** Média

---

## RF19 — Favoritar anúncio

O sistema deve permitir que um usuário autenticado adicione um anúncio à sua lista de favoritos.

**Prioridade:** Média

---

## RF20 — Remover favorito

O sistema deve permitir que um usuário autenticado remova um anúncio de sua lista de favoritos.

**Prioridade:** Média

---

## RF21 — Consultar favoritos

O sistema deve permitir que um usuário autenticado consulte sua lista de anúncios favoritos.

**Prioridade:** Média

---

# 5. Requisitos não funcionais

Os requisitos não funcionais abaixo descrevem **características e restrições esperadas do sistema em funcionamento**. Eles não especificam ferramentas, linguagens, frameworks, padrões de código ou formas de organização do desenvolvimento.

## RNF01 — Segurança das credenciais

O sistema não deve armazenar senhas de usuários em texto puro.

**Prioridade:** Alta

---

## RNF02 — Proteção de dados pessoais

O sistema deve restringir o acesso aos dados pessoais dos usuários às informações necessárias para o funcionamento da plataforma.

**Prioridade:** Alta

---

## RNF03 — Controle de acesso

Informações e operações que dependem da identidade do usuário devem estar disponíveis somente após autenticação.

**Prioridade:** Alta

---

## RNF04 — Privacidade dos anúncios

O sistema deve permitir que apenas o proprietário de um anúncio realize operações de gerenciamento sobre ele.

**Prioridade:** Alta

---

## RNF05 — Integridade dos dados

O sistema deve impedir situações que comprometam a consistência dos dados, como:

- anúncio associado a usuário inexistente;
- anúncio associado a plataforma inexistente;
- anúncio associado a categoria inexistente;
- duplicação do mesmo favorito para um usuário e anúncio;
- cadastro de usuário com e-mail já utilizado.

**Prioridade:** Alta

---

## RNF06 — Disponibilidade das informações públicas

Os anúncios classificados como disponíveis para consulta devem poder ser visualizados por visitantes sem necessidade de autenticação.

**Prioridade:** Alta

---

## RNF07 — Desempenho nas consultas

As consultas de anúncios e seus filtros devem apresentar tempo de resposta adequado para uma plataforma de pequeno e médio porte, evitando consultas desnecessariamente lentas à medida que a quantidade de anúncios aumenta.

**Prioridade:** Média

---

## RNF08 — Clareza das mensagens

Quando uma operação não puder ser realizada, o sistema deve apresentar uma mensagem clara que permita ao usuário compreender o problema.

**Prioridade:** Média

---

## RNF09 — Consistência das informações

As informações apresentadas ao usuário devem permanecer consistentes entre a listagem de anúncios e a visualização dos detalhes.

Por exemplo, um anúncio marcado como **Vendido** não deve ser apresentado em uma consulta de anúncios disponíveis como se estivesse disponível para negociação.

**Prioridade:** Alta

---

## RNF10 — Proteção contra operações não autorizadas

O sistema deve impedir que um usuário utilize sua autenticação para modificar, excluir ou gerenciar recursos pertencentes a outro usuário.

**Prioridade:** Alta

---

# 6. Regras de negócio

As regras de negócio complementam os requisitos funcionais e representam restrições específicas do domínio.

| ID | Regra |
|---|---|
| **RN01** | Um usuário pode possuir vários anúncios. |
| **RN02** | Cada anúncio pertence a um único usuário. |
| **RN03** | Um anúncio deve possuir uma única categoria. |
| **RN04** | Um anúncio deve possuir uma única plataforma. |
| **RN05** | Um anúncio deve possuir uma condição. |
| **RN06** | Um anúncio deve possuir uma classificação de completude. |
| **RN07** | Um anúncio deve possuir um status. |
| **RN08** | Um anúncio pode possuir várias fotos. |
| **RN09** | Um anúncio pode possuir uma foto principal. |
| **RN10** | Um usuário pode favoritar vários anúncios. |
| **RN11** | Um anúncio pode ser favoritado por vários usuários. |
| **RN12** | Um usuário não pode favoritar o mesmo anúncio mais de uma vez. |
| **RN13** | Somente o proprietário pode alterar ou excluir seu anúncio. |
| **RN14** | O preço de um anúncio deve ser maior que zero. |
| **RN15** | O e-mail de um usuário deve ser único. |
| **RN16** | Um anúncio vendido não deve ser tratado como anúncio disponível. |

# 7. Histórias de usuário

As histórias de usuário representam as necessidades dos usuários do sistema.

Formato utilizado:

> **Como** [ator], **quero** [objetivo], **para** [benefício].

---

## Épico 1 — Usuários e autenticação

### HU01 — Criar conta

**Como** visitante,  
**quero** criar uma conta informando meus dados,  
**para** poder publicar anúncios e utilizar recursos exclusivos para usuários.

**Relacionada:** RF01

### Critérios de aceitação

- [ ] Deve ser possível informar nome, e-mail e senha.
- [ ] O e-mail deve ser único.
- [ ] O cadastro não deve ser realizado se os dados obrigatórios forem inválidos.
- [ ] Após o cadastro, o usuário deve poder utilizar suas credenciais para realizar login.

---

### HU02 — Realizar login

**Como** usuário cadastrado,  
**quero** realizar login utilizando meu e-mail e senha,  
**para** acessar as funcionalidades que exigem autenticação.

**Relacionada:** RF02

### Critérios de aceitação

- [ ] Um usuário cadastrado com credenciais válidas deve conseguir se autenticar.
- [ ] Credenciais inválidas não devem permitir acesso.
- [ ] Após a autenticação, o sistema deve reconhecer o usuário nas operações protegidas.

---

# Épico 2 — Publicação e gerenciamento de anúncios

### HU03 — Publicar anúncio

**Como** usuário autenticado,  
**quero** publicar um anúncio de um produto retrô,  
**para** disponibilizá-lo para outros usuários da plataforma.

**Relacionada:** RF05

### Critérios de aceitação

- [ ] O usuário deve estar autenticado.
- [ ] O anúncio deve possuir título.
- [ ] O anúncio deve possuir descrição.
- [ ] O anúncio deve possuir preço maior que zero.
- [ ] O anúncio deve possuir categoria.
- [ ] O anúncio deve possuir plataforma.
- [ ] O anúncio deve possuir condição.
- [ ] O anúncio deve possuir completude.
- [ ] O anúncio deve possuir localização.
- [ ] O usuário responsável deve ser identificado pelo sistema.
- [ ] Um anúncio válido deve ser persistido.

---

### HU04 — Informar condição do produto

**Como** anunciante,  
**quero** informar a condição do produto,  
**para** que os interessados saibam seu estado de conservação.

**Relacionada:** RF05

### Opções

- Novo (Lacrado)
- Seminovo (Excelente)
- Usado (Bom estado)
- Recondicionado
- Com Defeito / Sucata

---

### HU05 — Informar completude do produto

**Como** anunciante,  
**quero** informar a completude do produto,  
**para** deixar claro se ele é completo, avulso ou incompleto/personalizado.

**Relacionada:** RF05

### Opções

- Completo (CIB)
- Loose (Avulso)
- Incompleto / Personalizado

---

### HU06 — Adicionar fotos

**Como** anunciante,  
**quero** adicionar fotos ao meu anúncio,  
**para** mostrar aos interessados o estado e as características do produto.

**Relacionada:** RF10 e RF11

### Critérios de aceitação

- [ ] Um anúncio pode possuir várias fotos.
- [ ] Uma foto pode ser definida como principal.
- [ ] As fotos devem estar associadas ao anúncio correto.

---

### HU07 — Editar anúncio

**Como** anunciante,  
**quero** editar meu anúncio,  
**para** corrigir ou atualizar suas informações.

**Relacionada:** RF06

### Critérios de aceitação

- [ ] O usuário deve estar autenticado.
- [ ] O anúncio deve existir.
- [ ] O anúncio deve pertencer ao usuário autenticado.
- [ ] Dados inválidos não devem ser aceitos.
- [ ] Um usuário não pode editar anúncio de outro usuário.

---

### HU08 — Retirar anúncio

**Como** anunciante,  
**quero** retirar meu anúncio,  
**para** impedir que ele continue sendo apresentado como uma oferta disponível.

**Relacionada:** RF07

---

### HU09 — Alterar status do anúncio

**Como** anunciante,  
**quero** alterar o status do meu anúncio,  
**para** informar se o produto está ativo, reservado, vendido ou inativo.

**Relacionada:** RF09

### Status

- Ativo
- Reservado
- Vendido
- Inativo

---

### HU10 — Consultar meus anúncios

**Como** usuário autenticado,  
**quero** visualizar os anúncios que publiquei,  
**para** acompanhar e gerenciar minhas ofertas.

**Relacionada:** RF08

# 9. Critério geral de pronto

Uma história poderá ser considerada concluída quando:

- [ ] o comportamento descrito na história estiver implementado;
- [ ] os critérios de aceitação forem atendidos;
- [ ] os dados necessários forem persistidos corretamente;
- [ ] situações de erro relevantes forem tratadas;
- [ ] operações protegidas respeitarem autenticação e autorização;
- [ ] a funcionalidade puder ser demonstrada por meio da API.

> **Atenção:** os itens acima são critérios funcionais de conclusão da funcionalidade. Eles não determinam linguagem, framework, arquitetura ou ferramenta de desenvolvimento.
